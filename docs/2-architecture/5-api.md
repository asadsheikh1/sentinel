# 06 — API Design

- **Style:** REST over HTTPS, JSON, versioned under `/api/v1`. The OpenAPI 3.1 schema is generated by FastAPI and published at `/api/v1/openapi.json`. Interactive docs are available only in non-production environments.
- **Authentication:**
  - Browser: a session cookie (`sentinel_session`, HttpOnly, Secure, SameSite=Strict) plus an `X-CSRF-Token` header on state-changing requests (double-submit token).
  - Machines (webhooks, CI): `X-Sentinel-Key: sk_live_<prefix>_<secret>`, with scopes.
  - GitHub webhooks: an `X-Hub-Signature-256` HMAC.
- **Authorisation:** each route declares a permission such as `incidents:read` or `actions:approve`. The role → permission map is in [Security](6-security.md).
- **Errors:** RFC 9457 `application/problem+json` (`type`, `title`, `status`, `detail`, `instance`, `errors[]`).
- **Pagination:** cursor-based (`?limit=50&cursor=<opaque>`). The response includes `next_cursor`.
- **Idempotency:** `Idempotency-Key` header on POSTs that create actions or ingest events.
- **Time:** RFC 3339 UTC everywhere.
- **Rate limits:** login 5/min per IP and account. General API 300/min per session. Ingest 600/min per key.

## 1. Endpoint catalogue

### Health and meta
| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/healthz` | none | Liveness |
| GET | `/readyz` | none | DB, Ollama, and telemetry backend reachability (no details leaked) |
| GET | `/api/v1/meta` | viewer | Version, git SHA, configured model names |

### Auth and users
| Method | Path | Permission | Purpose |
|---|---|---|---|
| POST | `/api/v1/auth/login` | public (rate-limited) | Email and password → session cookie |
| POST | `/api/v1/auth/logout` | session | Revoke session |
| GET | `/api/v1/auth/me` | session | Current user and permissions |
| GET/POST | `/api/v1/users` | `users:manage` | List or create users |
| PATCH | `/api/v1/users/{id}` | `users:manage` | Change role or deactivate |
| POST | `/api/v1/users/{id}/invite` | `users:manage` | Issue a new one-time invite (also used for password reset) |
| POST | `/api/v1/auth/accept-invite` | public (rate-limited) | Invite token + new password |
| GET/POST/DELETE | `/api/v1/api-keys[/{id}]` | `apikeys:manage` | Manage machine keys. The secret is shown once |

The generated per-route access table is in [rbac.md](../rbac.md).

## 3. API testing
- **Contract:** schemathesis (MIT) fuzzes the OpenAPI schema for 5xx errors and schema violations.
- **Authorisation matrix:** a parametrised pytest runs every route × every role (and anonymous), asserting the expected 2xx/401/403 responses. A route added without a permission declaration fails CI.
- **Webhooks:** recorded Alertmanager and GitHub payload fixtures, signature tests, and replay or idempotency tests.
